# Recruiter demo (90 seconds)

Start the app (`npm start`, then open http://127.0.0.1:5580) and press **90-second tour** in the top right. The tour drives
the same eight steps below. Each step names the real thing it shows.

| # | time | where | do | what it proves |
|---|---|---|---|---|
| 1 | 0:00 | Editorial · *Paper Orrery* | press Play, drag the frame slider | the whole pipeline runs live (stage timings and hashes in the rail); every frame is checked against the independent interpreter ("VM ≡ reference") |
| 2 | 0:12 | Syntax Furnace | click an AST node | real tokens and tree; the node's exact span is selected in the editor; the grammar rule that built it lights up |
| 3 | 0:22 | Editorial · *Type Mismatch* | read the C002 diagnostic, then change `radius: label` to `radius: 12` | parsing succeeds, checking fails at the precise span with a reason; the fix recompiles instantly |
| 4 | 0:32 | Type Observatory | filter the trace | scopes, symbols and the rule behind every expression's type |
| 5 | 0:42 | Optimization Duel · *Optimizer Bench* | press **Check equivalence** | struck-through instructions removed by real passes; 30 frames identical across reference, unoptimized and optimized VM; 29% fewer VM instructions (measured) |
| 6 | 0:55 | Bytecode Theater · *Fibonacci Steps* | click the gutter on line 9, Continue, Back, **Prove replay** | a real step debugger over bytecode; time travel; rewound state hash = fresh replay hash |
| 7 | 1:10 | Failure Gallery | **Compile with the bad pass**, then **Reduce** | a deliberately wrong optimization is caught by the oracle, then shrunk to a 7-line reproducer |
| 8 | 1:20 | Proof Cabinet · *Rainfall Ledger* | **Record run**, **Reproduce**, **Tamper: bytecode** | the server recompiled to the same bytes as the browser; the receipt reproduces; tampering is rejected |

## Three real debugging moments from building it
1. **A grammar bug found by the example corpus.** `size` and `from` were keywords, so `text(..., size: 12)`
   failed to parse in 10 of 13 examples. They became contextual words, recognised only in scene headers and
   data declarations, with a test.
2. **A time-travel bug found by the replay proof.** Rewinding *forward* to a later checkpoint restored the
   scene's command list by truncating it to a saved length, which padded the array with holes. The
   replay-equality test caught it at step 95. Snapshots now copy the (immutable) command references.
3. **A misleading benchmark found by interleaving.** The first benchmark showed a ×6.4 speed-up on a
   sub-millisecond example. It was JIT warm-up: "off" always ran first. With off/on runs interleaved, the
   result fell to ×1.01–×1.10 across later runs. The ledger records both.

## Numbers you can quote (all regenerated by commands in the README)
- 93 Vitest tests + 9 Playwright E2E tests, all passing.
- Differential fuzzing: 2,000 seeds × 2 configurations = 4,000 runs, 4,000 agreeing, 0 rejected, 0 compiler
  crashes on 2,000 mutated sources (`evidence/fuzz-summary.json`).
- Optimizer: 6–29% fewer VM instructions across the 13 examples (deterministic counts). Median wall time:
  ×1.05–×1.27 in the recorded run (`evidence/benchmarks.json`). Earlier runs on the same busy machine gave
  ×1.01–×1.33, so differences under about 10% are within run-to-run noise, and the docs say so.
